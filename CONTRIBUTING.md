# Contributing

Tools change, links break, and scam patterns shift, so the roadmap needs regular corrections from people who do this work.

## What we accept
- Corrections: broken links, outdated tools, factual errors. Open an issue or send a pull request directly.
- Better labs. If you have a stronger hands-on exercise for a day, propose it. A lab where the learner builds an artifact beats one where they only read.
- New days or topics. Open an issue first so we can agree on scope and where the day fits before you write it.
- Translations. Follow the structure of an existing phase, and open an issue first so two people don't translate the same phase.
- Changes to `skill/`, including new reference checklists. The scope and ethics section in [`skill/SKILL.md`](skill/SKILL.md) can be tightened but not loosened.

## What we don't accept
- Content that requires unauthorized access, targets private individuals, or teaches an offensive technique without an authorized, defensive purpose.
- Content that only works with a paid tool when a free alternative exists, unless the free alternative is listed next to it.
- Vendor marketing presented as curriculum.

## Process
1. For anything larger than a small fix, open an issue describing the change and wait for agreement on direction before writing it.
2. New or rewritten days follow [`curriculum/_template.md`](curriculum/_template.md). Each day needs a Practical section that names a tool and the artifact the learner builds. A reading list alone does not count.
3. A maintainer reviews the change for accuracy, for the ethics boundary, and for fit with the rest of its phase. Minor style issues will not block a merge.

## Ground rule
Every contribution stays within authorized, defensive, lawful use, the same as the rest of the roadmap. The [README](README.md#ethics-and-ground-rules) has the full rules.
